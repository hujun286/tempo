## §1 这个项目是干嘛的

**一句话**：连上期货公司 CTP 柜台行情前置（16 条链路），实时收 tick，聚合成**每分钟一根的 K 线（OHLCV）**，落盘成 Parquet，供后续回测/分析。

**数据流向**（记牢这条链，所有代码都在干这四件事之一）：

```
CTP前置(16个IP)  ──tick──▶  SPI回调(行情.rs)  ──▶  聚合器(按 合约+分钟 攒桶)
      ──每分钟收盘──▶  MinuteBar  ──通道──▶  落盘线程  ──追加一行JSON──▶  bars_日期.jsonl
      ──(收盘/手动)──▶  合并程序  ──读jsonl去重排序──▶  bars_日期.parquet (13列)
```

**为什么 16 条链路**：CTP 单个前置有流量限制，用 16 个 member（多账号/多前置）分片订阅不同合约，合起来吃下全市场。**这是本项目的特色，也是最容易出坑的地方**（见 §13）。

## §5 时间口径（本项目最烧脑，务必吃透）

**三套时间，各管各的，绝不能混**：

| 字段 | 来源 | 用途 | 时区影响 |
|---|---|---|---|
| `bar_time` | CTP 的 `TradingDay+UpdateTime+UpdateMillisec` 还原的 **UTC 瞬时** | K线时间轴 | 无（是绝对瞬时） |
| `trading_day` | **CTP 柜台直接给的 `TradingDay`**（权威！） | **切交易日的唯一键** | 无 |
| 文件名日期 | 本机墙钟（聚合时 `Local` 转） | 仅归档 convenience | **有**：跨时区/夏令时会和交易日错开 |

**铁律**：
1. **下游取"某交易日数据"永远 `WHERE trading_day='YYYYMMDD'`，绝不用文件名**。因为一个交易日的夜盘(21:00起)被墙钟午夜劈进两个文件。
2. **交易所以数据时间为准，不看本机时钟**。用户机器伦敦时间，**不改时区也没问题**——OHLC、分钟归属、trading_day 全用 CTP 给的值，与本机几点无关。
3. **⚠️ 未处理的坑（v1.5 要做）**：夏令时切换那一小时（伦敦 10月末/3月末），`bar_time` 墙钟会重复或跳号，而 `trading_day` 柜台给——两套时钟打架。当前代码没做单调性校验，v1.5 应加 tick 时间回拨检测。

## §9 Parquet 输出 schema（13列，下游按此读）

`bar_time`(UTC瞬时) · `instrument_id` · `trading_day`(字符串日期,**查询认这个**) · `open`/`high`/`low`/`close` · `volume`(CTP当日累计) · `turnover`(累计) · `volume_1m`(单分钟增量) · `turnover_1m`(增量) · `open_interest` · `is_gap`(bool,补的空bar为true)

**⚠️ 下游注意**：`volume`/`turnover` 是**当日累计值**，直接当"单分钟量"用会严重偏大。**单分钟量请用 `volume_1m`/`turnover_1m`**。首根bar的增量=累计本身（差分边界，单测 `增量首根等于累计` 已覆盖）。

查询范例：
```sql
SELECT * FROM read_parquet('data_数据/分钟K线/bars_*.parquet')
WHERE trading_day='20261124' ORDER BY bar_time;   -- glob所有文件，认字段不认文件名
```

## §13 血泪踩坑（全是真踩出来的，新窗口不写给他必踩）

| 坑 | 教训 |
|---|---|
| **`dubious ownership` 让 git 静默失败** | `/data/workspace` 属主nobody，`git log` 显示空但仓库在。`git config --global --add safe.directory /data/workspace`。**跨环境通用**，用户机器上也会遇到 |
| **中文文件名 vs `mod` 声明对不齐** | Rust `mod 聚合;` 必须找 `聚合.rs`。改中英文文件名要**文件名+mod声明+`crate::路径`三处同步改**，漏一处=几十个"找不到模块"错。**结论：文件名用英文、代码内容(类型/变量/注释)用中文，最省心** |
| **格式串参数靠肉眼数会漏** | `[MERGE]...{}...{}` 5占位符只给4参数，肉眼扫过没发现，编出50错。**用 `检查格式串.py` 自动关卡**，别信眼睛 |
| **行号不能判断文件新旧** | 只补一个参数、总行数不变→行号一样。用户以为编的是新文件其实是旧的。**验货看内容(grep那行有没有`date,`)，不看行号** |
| **沙盒无 cargo** | 我这边从没编译过交付的.rs，静态关卡全过但类型层没验。第一次`cargo build`冒小错正常，整段报错发来，别自己动聚合/落盘/CTP |
| **15G写盘 vs 追加分片** | 每2分钟全量重写=15G(已废)；每根bar追加一行=全天几百MB(现行)。**看到"全量重写"就是退回到v1.2的错误方案** |
| **二次Ctrl+C全丢** | v1.1全天攒内存，第二次Ctrl+C `exit(130)`强杀=当天全丢。**v1.4追加分片后强杀也只丢60秒**，但养成习惯：按一次，等"共N根"再走 |
