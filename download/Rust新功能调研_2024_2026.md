## 1. Stable 已落地的语言/库新功能（1.77 → 1.100+）

### 1.1 Edition 2024（1.85 稳定，2025-02-20）
来源：https://blog.rust-lang.org/2025/02/20/Rust-1.85.0 、https://doc.rust-lang.org/edition-guide/rust-2024/rpit-lifetime-capture.html

| 功能 | 说明 | 对本项目的用途 |
|---|---|---|
| async closures（RFC 3668，1.85 stable） | `async || {}`、`AsyncFn/AsyncFnMut/AsyncFnOnce` trait | tokio 任务闭包更自然：可借用捕获后直接 await，替代「闭包返回 async block」的变通写法 |
| RPIT lifetime capture rules 2024（RFC 3498） | 返回 `impl Trait` 默认捕获所有在作用域的 lifetime/type；配合 1.82 的 `use<..>` precise capturing 可精确控制 | K 线缓冲区返回 `impl Future/Iterator` 时的生命周期语义更直观，减少 `+ 'a` 补丁 |
| `unsafe extern` 块（RFC 3484，1.82 起） | extern 块内需显式标注 unsafe 内容 | CTP bindgen 生成代码升级到 2024 edition 后 unsafe 边界显式化 |
| unsafe attributes | `#[unsafe(no_mangle)]` / `#[unsafe(export_name)]` / `#[unsafe(link_section)]`（1.82 起） | CTP 回调导出函数（`OnRspDepthMarketData` 桥接等）必须改写 |
| `static_mut_refs` 由 warn 变 deny | 静态可变引用检查收紧 | 若有全局 CTP 状态指针式访问需改 `&raw`/`UnsafeCell` |
| `if let`/tail expr 临时作用域、宏片段 `expr` 顺序 | 语义微调 | cargo fix --edition 可自动迁移大部分 |

迁移方式：`cargo fix --edition`；1.85 的 cargo 已支持 edition 2024。

### 1.2 语言/库功能速查（按版本，均核对 releases.rs）
- **1.77.0（2024-03-21）**：**C 字符串字面量 `c"…"`**；`static_mut_refs` lint。FFI 里传 `&CStr`/CTP 字符串字段时直接 `c"InstrumentID\0"`，省去 `b"...\0 as *const _` 样板。
- **1.79.0（2024-06-13）**：**`inline const {}` 表达式**（const 上下文内联求值）；Wasm target features。
- **1.82.0（2024-10）**：`&raw const` / `&raw mut` 操作符（替代 `addr_of!/addr_of_mut!`）；**`unsafe extern` 块**；**precise capturing `use<..>`**（RFC 3617）；`offset_of!` 嵌套字段；inline asm 的 const 操作数；const fn 浮点运算；unsafe attributes。
- **1.84.0（2025-01）**：平台支持与 lint 调整为主（细节见 releases.rs，无重大语言项）。
- **1.85.0（2025-02-20）**：**Edition 2024**、**async closures**。
- **1.86.0（2025-04-03）**：**trait upcasting（trait object 向 supertrait 上转型）**；**safe 函数可加 `#[target_feature]`**；`HashMap/slice` 的 `get_disjoint_mut`（多 key 并发可变访问）（来源 releases.rs/docs/1.86.0/，`get_disjoint_mut` 条目待验证）。
- **1.87.0（2025-05-15）**：i686 目标强制 SSE2 并用它传 SIMD 类型；放宽 RPIT in trait 的 bounds；库侧含 `std::io` 匿名管道相关稳定（待验证）。
- **1.88.0（2025-06-26）**：**let chains（`if a && let Some(x) = b && …`，仅 2024 edition）**；**naked functions（`#[naked]` 全函数汇编）**；`slice::as_chunks`/`as_rchunks` 等（待验证）。来源：https://blog.rust-lang.org/2025/06/26/Rust-1.88.0
- **1.89.0（2025-08-07）**：**`generic_arg_infer`（const 参数可写 `_` 自动推断，如 `Foo<_>`/数组 `[_; _]`）**；`mismatched_lifetime_syntaxes` lint（FFI 返回类型生命周期书写不一致自动告警）。另：x86_64-apple-darwin 降为 Tier 2。
- **1.90.0（2025-09-18）**：lint 拆分与诊断改进为主；cargo 有构建输出目录变化传闻，待验证。
- **1.91.0（2025-10-30）**：模式绑定按书写顺序 drop（`let (a, b) = …` 的 Drop 顺序语义化）。
- **1.92.0（2025-12-11）**：never 类型相关 coercion 改进（返回 `Result`/`ControlFlow` 中传播 `!` 免手动 unreachable）。
- **1.93.0（2026-01-22）**：**C 风格可变参数函数的声明（c_variadic）稳定**（定义变参 C 兼容函数）；s390x 向量 target features。
- **1.94.0（2026-03-05）**：RISC-V 29 个 target features；impl 继承 trait 的 dead_code lint 级别。
- **1.95.0（2026-04-16）**：**match 臂上的 `if let` guard**；路径段关键字 import；LLVM 22。
- **1.96.0（2026-05-28）**：cfg 中可用 expr 宏变量；元组中 never 类型 coercion。
- **1.97.0（2026-07）**：`dead_code_pub_in_binary`（bin crate 中未用 pub 项告警）；`cfg(target_has_atomic_primitive_alignment)`；import 尾随 self。
- **1.98.0（2026-08）**：**`&mut T` 可直接 coerce 到 `&Cell<T>`**；`c_void_returns` lint（FFI 返回 `core::ffi::c_void` 检查）；runtime 符号定义 lint。
- **1.99.0（2026-10-01）**：`raw_borrows_via_references` lint（引用立刻退化成裸借用的检查，FFI 侧很有用）。
- **1.100.0（2026-11-12）**：**allocator_api 核心部分稳定**（自定义 Allocator 的库级 API）；**Cargo 原生报告未使用依赖**（博客小节 Reporting unused dependencies in cargo）。来源：https://blog.rust-lang.org/2026/11/12/Rust-1.100.0 、cargo-shear README。
- **1.101.0（beta，2026-12-24 转 stable）**：`slice::split_once` 系列稳定、`IoSlice` 部分 const 化、**`inline` 属性作用于 async fn 生成的 poll 函数**（对 tokio 热路径内联优化有用）。

### 1.3 对 CTP C++ FFI 绑定特别有用的（汇总）
1. `unsafe extern` 块 + unsafe attributes（1.82/2024 edition）→ bindgen 产物与导出回调写法升级。
2. `&raw const/&raw mut`（1.82）→ 替代 `addr_of!`，读 CTP 结构体字段指针更直接。
3. `c"…"` 字面量（1.77）→ 合约号/BrokerID 等常量字符串。
4. `mismatched_lifetime_syntaxes`（1.89）、`c_void_returns`（1.98）、`raw_borrows_via_references`（1.99）三个 lint → FFI 层卫生检查。
5. naked functions（1.88）→ 手写回调 trampoline（如需固定 ABI 的汇编 shim）。
6. C 风格变参函数声明（1.93）→ 对接 C++ 侧 printf 式日志回调。
7. `&mut T → &Cell<T>` coercion（1.98）→ 共享回调状态容器（`Cell<AtomicU64>` 计数器）少写 cast。

## 4. Parquet / Arrow 生态（重点）

### 4.1 arrow-rs 主线版本要点（均核对 GitHub releases）
来源：https://github.com/apache/arrow-rs/releases （API 抓取）、https://arrow.apache.org/blog/2025/10/30/arrow-rs-57.0.0

| 版本 | 时间 | 与时序落盘/读库直接相关的变化 |
|---|---|---|
| **57.0.0** | 2025-10-30 | **自定义 thrift 解码器使 Parquet metadata 解析提速约 4x**（大量列/多文件场景收益大）；新增 **arrow-avro** crate；**Variant 类型读写 Parquet（含 shredded）**；Parquet Geometry/Geography 类型；Parquet push decoder（元数据先行、按 range 推送解码）路线落地（见 issue #8463） |
| 58.x / 59.x | 2026 上半年 | Parquet 加密算法扩展；**arrow-ipc sans-IO 流式编码器**（59.2）；parquet-index 支持列路径；Variant `variant_to_arrow` Map/REE 支持；DELTA_BYTE_ARRAY 大值修复 |
| **60.0.0** | 2026-09-15 | **`PageIndexBuilder`/`PageIndexProvider`**（Parquet Page Index 读写完整化）；**ALP 编解码**（浮点列压缩更优）；新增 `PageIndex` 结构体；INT96 timestamp `ColumnOrder`；清理大量 deprecated API（升级时注意 break） |
| **60.1.0** | 2026-10-28 | **`ParquetPushDecoder::scan_plan`（读前预读规划）**；**per-column data page row count limit**（可控制单页行数，利于按时间追加/按区间读取）；INT96 时间戳统计转换；ByteStreamSplit/ALP 编解码器实验性公开 |
| **60.2.0** | 2026-11-21 | **PageIndex 后端存储改进**；Bloom filter 读写修复与 `ArrowSbbf`（用 Arrow 数组查 Parquet bloom filter）；`ParquetMetaDataReader` 可取 bloom filter；缓存文件 KV 元数据可更新 |

### 4.2 对「每日更新版落库影响大」的解读
- **读端（落库/对账侧）**：57.0 的 4x metadata 解析 + 60.1 的 push decoder/scan_plan + 60.2 的 PageIndex 改进，意味着「打开文件→按列/按行组过滤→批量读 RecordBatch」的延迟显著下降；对每日增量文件合并、快速按合约+时间窗抽取列非常有利。
- **写端**：per-column data page row count limit（60.1）+ PageIndex（60.0/60.2），配合显式 WriterProperties（压缩、字典页、页大小），可以把分钟 K 线文件按天/合约切片组织，落库侧可用 PageIndex/bloom filter 只读相关行组。
- **压缩**：parquet crate 默认压缩仍是 Snappy（docs.rs/parquet 文档）；**zstd 级别默认值近两年是否有变化未逐版核实 → 待验证**。建议显式 `set_compression(ZSTD(level))` 并做体积/速度基准，避免依赖默认值。
- **Schema evolution**：Parquet 类型提升（如 int32→int64）读取支持在 arrow-rs 已有；新增列/字段 ID 往返等能力的确切版本待验证（ arrow-rs 近期未把 schema evolution 列为 release 主打项）。13 列固定 schema 的项目可暂不依赖。
- **异步读写**：`parquet::arrow::async_reader/async_writer`（tokio 集成，`tokio`/`async` feature）为现有能力，文档见 https://docs.rs/parquet ；57-60 间接口有更名/清理（60.0 删除 deprecated 函数），升级需过编译修复。
