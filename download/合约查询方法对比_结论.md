# 期权合约存在性判定：用户边界探测法 vs 现行订阅确认法（对比结论）

> 时间：2026-11-27 23:00（北京时间）｜结论：**两种方法融合，以"订阅确认+宽网格"为主**
> 证据基础：当晚夜盘 31,362 tick 真实数据 + 白天 13:30 窗口 + 更新器 v1 全天运行结果

## 一、两种方法是什么

**用户法（边界探测/二分缩围）**：向 16 前置不断尝试查询边界行权价（如 au2702C1568）的
tick 报价，无 tick 就向中间缩小范围；一旦知道最大/最小行权价，"中间的期权合约必然存在"，
几万个中间合约就完全不用查询。

**现行法（订阅确认，合约清单更新器 v1 已实装）**：把候选合约批量向 CTP 行情前置订阅，
`on_rsp_sub_market_data` 回报 `ErrorID==0` = 交易所确认存在，`ErrorID!=0` = 交易所明确
告知不存在（如合约代码非法/摘牌）。存量 29,434 条已用此法验证 100% 存活。

## 二、关键实测证据：tick 回包不能当存在性信号

今晚夜盘数据给出了一个教科书级反例：

| 合约 | 真实状态 | 夜盘 tick | 白天 tick | 订阅确认 |
|------|---------|-----------|-----------|---------|
| au2702C768（平值！） | 存在且下午有 152 笔真实行情 | **0**（全程无回包） | 152 | ErrorID==0 ✅ |
| ag2702P9000（深虚值） | 存在 | 1,590 | - | ErrorID==0 ✅ |

如果用"无 tick → 不存在 → 缩小范围"的逻辑跑夜盘，**会把平值合约 au2702C768 误判为
不存在并把它"缩"出范围**——边界探测法在流动性稀疏的窗口（夜盘、冷门月份、深虚值档）
会系统性误删。CTP 里"存在"和"有行情"是两件事：存在性由交易所挂牌决定，tick 由成交/
报价活动驱动。

## 三、用户法的真价值与融合方案

用户思路里有两个正确且已被吸收的内核：

1. **"知道边界就免查中间"——对，但存在性判定不能用 tick，要用订阅确认**。
   落地 = 宽网格订阅：一次会话订阅全部候选档位（今晚 82 条：au 700-844/8 × 2 + ag
   9000-11000/100 × 2），CTP 一轮回报就把整个存在集合建完——不存在的档位直接回错误码，
   存在的回确认，**没有任何"几万个查询"成本**（今晚实测一轮 82 订阅 0 秒级延迟）。
2. **边界探测思想用于"摸挂牌边界"**：今晚网格全档 82/82 存在 = 网格还没触及交易所挂牌
   边界。下一步在更新器 v2 里加边界外推二分：对网格外侧候选（au<700、ag<9000、两翼
   上界）继续小步订阅确认，直到撞到第一个 ErrorID!=0，即得真实挂牌区间——这正是
   "二分缩小范围"，只是判定信号从 tick 换成订阅确认。

融合后的三条判定规则（写进更新器 v2 规格）：

```
存在性   = 订阅确认 ErrorID==0（权威，交易所口径）
流动性   = tick 到达频率（只做活跃度分层，绝不反推存在性）
静态字段 = 交易所官网清单（到期日/乘数 CTP 无接口，动态抓取流程继续）
```

## 四、成本对比

| 维度 | 边界探测(tick 版) | 订阅确认+宽网格(现行) |
|------|------------------|---------------------|
| 判定准确率 | 夜盘/冷档系统性误删 | 交易所口径 100% |
| 会话数 | 需反复试（二分多轮） | 一轮全网格 + 边界外推小步 |
| 依赖 | 需要行情活跃（夜盘失效） | 盘中盘后均可（确认回报与成交无关） |
| 额外收益 | 无 | 存在清单直接可当订阅清单喂采集器 |

**结论一句话**：用户的"免查中间"直觉是对的，实现载体从"tick 二分"升级为
"订阅确认网格+边界外推"，既保留省查询的优点，又消灭了流动性误判——今晚的
au2702C768 就是活证据。
