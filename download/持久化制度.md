# 持久化制度（第 3 棒起执行，任何工作先过此关）

## 背景
2026-11-25 会话实例被回收，/home/xx/ 工作目录消失，仅靠用户手动上传 Gitee 的
combined-backup-20261126_031954.tar.gz 恢复。为此固化以下四层体系，缺一不可。

## 四层体系
| 层 | 载体 | 动作 | 责任方 |
|---|---|---|---|
| L1 活工作区 | /home/z/my-project/（沙盒保留盘） | 一切新产物**先写这里**，只增不删 | AI |
| L2 版本历史 | 同目录 git 仓库 | 每个工作节点 `git add -A && git commit`，永不 reset/丢弃历史 | AI |
| L3 快照包 | download/快照_时间戳.tar.gz | 每个工作节点结束自动打包（<50MB，IM 可传） | AI |
| L4 异地容灾 | 用户 GitHub(hujun286/tempo) + Gitee(zz237/...) | 用户把快照包上传 | 用户 |

## 硬性规则
1. **任何实验性/中间产物也留底**：进 archive_已弃用存档_永不删除_仅留历史参考/ 目录（沿用工程惯例），不进 .gitignore。
2. 文档四份（交付说明_上机步骤 / 交接报告_CTP分钟K线_第3棒 / 决策日志_推理链 / 工作日志_第3棒）为**活文档**，实时增量追加，禁止整篇重写丢历史。
3. 敏感信息（账号/密码/AuthCode）：只进 config/secrets*.toml，该文件默认不入 git（.gitignore 管控），只随快照包走 L4。
4. 沙盒网络事实（实测 2026-11-26）：Gitee ✅ / rsproxy ✅ / 阿里pypi ✅ / GitHub raw ❌ / 清华pypi ❌403。下载类一律先 Gitee/rsproxy/阿里。
