## 三、合并策略（回答"选定软件怎么合并进咱们项目 + 以后追更新"）

三方案对比（结合本工程"沙盒易回收+Gitee 容灾"的现实）：

| 方案 | 优点 | 缺点 | 判定 |
|------|------|------|------|
| **A. crates.io 锁版本**（Cargo.toml 钉死 x.y.z + Cargo.lock 入库） | 零维护、编译快、审计有 RUSTSEC 兜底 | 上游新功能要手动升版本 | **首选**（implied-vol/black_scholes/volsurf/barter 等一切在 crates.io 的） |
| **B. git subtree 进 workspace** | 单仓库自包含、history 可追 | subtree pull 冲突处理烦；仓库体积膨胀（与"zhipu 瘦身"矛盾） | 不用 |
| **C. 独立克隆 + 上游清单**（`期权工具研究/上游克隆/` + `上游清单.toml` 记 URL/commit/用途） | 随时 `git pull` 追上游；主仓库不受污染；克隆可 --depth 1 | 每次沙盒回收要重新克隆（39 秒级，走 ghfast.top 镜像） | **仓库级工具用这个**（OptionStratLib/OCB/tfrmma 双引擎） |

**落地规则（写进工作制度）**：
1. 数学库走方案 A：本报告锁定 `implied-vol 2.1.0 / black_scholes 0.11.1 / volsurf 4.0.1`，
   升级节奏=每季度或安全公告触发，升级前跑本演示 crate 当回归测试（5 演示就是回归基线）。
2. 仓库级走方案 C：`上游清单.toml` 是唯一台账，追更新=每季 `git -C <克隆> fetch && log` 看上游，
   有需要的 commit 就 rebase 我们的无侵入分支（我们的适配代码**绝不写进上游克隆**，
   一律放在自己的适配 crate 里，升级零冲突）。
3. OptionStratLib 若正式引入：锁 GitHub tag `0.24.x`，feature 只开 chains+pricing 不开 plotly。

## 四、CTP 适配层设计（下一步实装建议）

```rust
/// CTP tick → 期权定价输入参数 适配层（放我们自己的 crate，绝不改上游克隆）
/// CTP 行情快照无期权静态字段（行权价/方向在合约名里），语义解析已在探针中验证。
trait CtpTickToPricingInput {
    /// 从 DepthMarketData + 合约名解析出定价四元组
    /// 返回 None = 该 tick 无效价或解析失败（CTP 无效价过滤已在探针实现）
    fn to_pricing_input(&self, 到期日: chrono::NaiveDate, r: f64) -> Option<PricingInput>;
}

struct PricingInput {
    行权价: f64,        // 合约名解析（SHFE au2702C768 / CFFEX IO2612-C-4400 两规则已验证）
    方向: OptionType,   // C/P
    远期价: f64,        // 标的期货最新价（同 tick 批次内取，期货即远期）
    市场价: f64,        // 最新价；无效时用 (买一+卖一)/2 中间价（tick 级标准做法）
    t年化: f64,         // (到期日-交易日)/365，T 型报价日历自行实现（中国节假日表）
}

/// 三条落地管道（按优先级）：
/// 1. tick→IV 实时管道：订阅夜盘验证过的活跃档位（存在清单 82 条已实存）
/// 2. IV→SVI 曲面管道：每分钟全档位重拟合（volsurf calibrate <40ms 已实测）
/// 3. 曲面→做市报价管道：对接 tfrmma quoting-engine 的 Avellaneda-Stoikov（IV 空间）
```

## 五、踩坑记录

1. **沙盒后台进程活不过单次命令**（nohup/setsid 均被清）：长任务必须"单窗口制"程序
   + cron 定时拉起，这直接催生了期权夜盘采集器的架构（今晚 22:10 cron 窗口实证有效）。
2. **磁盘 100% 根因是 target/**（md_probe+ibx 累计 4.7GB）：`rm -rf target` 释放 50%；
   编译产物一律视为可丢弃，重要源码即时 git 提交。
3. **子代理 Task 基础设施三次超时**（"check existing record: context deadline exceeded"）：
   同一任务连续失败就转自办（本报告即自办产出）；但子代理死前的部分成果（上游克隆）有效保留。
4. **optionstratlib 不在 rsproxy sparse 索引**（NoSuchKey）：调研报告的 crates.io 链接与实测不符，
   按 GitHub tag + ghfast.top 镜像克隆解决。凡"调研说在 crates.io"必须实测索引为准。
5. **volsurf 默认 DataFilter 没滤掉坏报价**（K=9900 的 22% IV 拉高 RMSE 到 8.58%）：
   接入生产前要自己实现"报价陈旧度过滤"（tick 时间戳距最新 >N 秒的档位剔除）。
6. **au2702 期权夜盘零行情**（同会话 ag 期权大量成交，下午盘 au 正常）：发现级实测结论，
   原因待核（交易所夜盘期权品种范围/维护窗口），已记工作日志，以交易所公告为准。
7. RustQuant crates.io 最新 0.3.1（2024-11）远落后 GitHub（2026-10 推送）——零件库若要用，
   走 GitHub path 依赖并锁 commit，不走 crates.io。
