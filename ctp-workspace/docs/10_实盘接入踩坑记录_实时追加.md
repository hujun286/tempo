## 1. `git commit -m` 里 `!` 被 bash 历史展开吃掉

- **现象**：`git commit -m "... match→matches!、collapsible_if ..."` 报 `-bash: !、collapsible_if: event not found`；commit 仍成功，但 message 里 `match→matches!、collapsible_if` 整段丢失。
- **根因**：bash 交互式 shell 默认开启 history expansion（`!` 触发），双引号内 `!` 后跟非空格字符会被当作历史引用展开。
- **解决**：`git commit -m` 一律用**单引号**；或改用 `git commit -F message.txt`。单引号内 `!` 不展开。
- **验证**：`git log -1 --format=%B <hash>` 对比 message 完整性。
- **教训**：commit message 里「半角 `!` + 紧邻英文标识符」是最容易踩的组合（全角 `！` 没事）。

## 2. cargo deny 0.20.2 没有 `--disable-fetch`

- **现象**：`cargo deny check --disable-fetch` 报 `unexpected argument '--disable-fetch' found`。
- **根因**：`--disable-fetch` 是旧版标志，0.20.2 中对应的是全局 `--offline`。
- **解决**：`cargo deny --offline check`——`--offline` 放在 `cargo deny` 之后、子命令之前。
- **验证**：`cargo deny --help` 中存在 `--offline  Disables fetching crates, advisory databases, and std-replacement-data`。
- **教训**：cargo 生态工具的全局标志位置不统一。报 `unknown argument` 时先看 `--help` 确认标志是否存在及其位置，不要凭记忆写。

## 3. cargo deny `[advisories] db-path` 必须指向本地 git 仓库

- **现象**：`cargo deny check` 报 `failed to fetch advisory database https://github.com/RustSec/advisory-db with cli`，实际从 `rsproxy.cn` 镜像拉取并 404。
- **根因**：
  1. 项目根没有 `deny.toml`，deny 走默认配置，默认 db 经 rsproxy 镜像拉取，镜像返回 404。
  2. 本地目录 `/home/xx/projects/advisory-db-main/advisory-db-main/` 无 `.git`，deny 不接受非 git 仓库作为 db。
- **解决**：
  1. `git clone --depth=1 https://github.com/RustSec/advisory-db.git /home/xx/projects/advisory-db-main/advisory-db-main`，让本地 db 成为 git 仓库。
  2. `deny.toml` 中写 `[advisories] db-path = "/home/xx/projects/advisory-db-main/advisory-db-main"`（指向 db 本身，不是父目录）。
  3. 运行时用 `cargo deny --offline check` 强制不联网。
- **验证**：`cargo deny --offline check` 输出 `advisories ok, bans ok, licenses ok, sources ok`。
- **教训**：cargo-deny 对本地 db 有「必须是 git 仓库」的硬要求，普通目录不行。

## 4. cargo audit `[database]` 段必须带 `stale = true`

- **现象**：`~/.cargo/audit.toml` 只写 `[database] path = "..."` 后，`cargo audit` 报 `missing field stale`。
- **根因**：cargo-audit 0.21+ 的 `[database]` 段 `stale` 字段必填，表示是否接受超过 90 天未更新的本地 db。
- **解决**：`[database]` 段写全三个字段：

  ```toml
  [database]
  path = "/home/xx/projects/advisory-db-main/advisory-db-main/"
  fetch = false
  stale = true
  ```

- **验证**：`cargo audit` 输出 `Scanning Cargo.lock for vulnerabilities (68 crate dependencies)`。
- **教训**：cargo audit 与 cargo deny 配置字段不同——audit 用 `[database] path`，deny 用 `[advisories] db-path`，不能混用。

## 5. cargo deny licenses 报 unlicensed 指本 crate 未声明

- **现象**：`cargo deny check licenses` 报 `error[unlicensed]: rust_ctp_test = 0.1.0 is unlicensed`。
- **根因**：`Cargo.toml` 的 `[package]` 段缺 `license` 字段。cargo-deny 默认检查所有 crate（含 workspace 内部），本 crate 未声明 license 即报错，与第三方依赖无关。
- **解决**：`Cargo.toml` 增加 `license = "MIT"` 与 `authors = ["Placeholder Author <placeholder@example.com>"]`。项目有发布计划，选 MIT。
- **验证**：`cargo deny --offline check` 输出 `licenses ok`。
- **教训**：`unlicensed` 与 `unmatched-license` 是两回事——前者指本 crate 没声明 license，后者指依赖的 license 类型不在白名单。

## 6. deny 失败明细用 `grep -E '^error'` 抓全

- **现象**：用 `grep -E 'error\[|unmatched|not explicitly allowed|rejected'` 过滤 deny 日志，漏掉 `error[unlicensed]`，导致误判问题所在。
- **根因**：deny 的错误类型标签（unlicensed / unmatched-license / banned / denied 等）分散，关键词白名单无法穷举。
- **解决**：deny 失败明细一律 `grep -E '^error'` 抓全部 error 行，不按关键词过滤。
- **验证**：`grep -E '^error' /tmp/deny.log` 输出所有错误。
- **教训**：错误分类抓取用标签前缀（`^error`），不用关键词枚举——前者稳定，后者易漏。

## 7. `cargo clippy --all-targets` 看不到未 `pub mod` 的目录

- **现象**：`trading_gateway/` 下写完 4 个文件，`cargo clippy --all-targets` 完全无报错，`Finished 0.03s`。
- **根因**：`trading_gateway/` 未在 `lib.rs` / `main.rs` 中被任何 `mod` 声明引用，cargo 不知道它存在，clippy 不检查。
- **解决**：临时 `echo 'pub mod trading_gateway;' >> src/lib.rs`，跑完 clippy / build 后 `sed -i '/^pub mod trading_gateway;$/d' src/lib.rs` 撤销。每个新文件验证都需如此，直到最终 `main.rs` 加 `mod trading_gateway;` 永久挂载。
- **验证**：临时 `pub mod` 后 `cargo clippy --release --lib` 输出 `Checking rust_ctp_test`，说明真正编译了。
- **教训**：`cargo check` / `cargo clippy` 输出 `Finished in 0.0Xs` 且无 `Checking` 行 = 什么都没编译，不是「通过」。判断依据是输出中是否有 `Checking <crate>` 行。

## 9. `strings` 遇 UTF-8 中文截断，改用 `grep -a`

- **现象**：`strings binary | grep libthosttraderapi` 只输出 `/lib/libthosttraderapi_se.so`，短一截；预期为 `/home/xx/projects/ctp-workspace/ctp_live_实盘接入工程/lib/libthosttraderapi_se.so`。

## 10. 脚本改文件前必须先 `cat` / `grep` 确认当前格式

- **现象**：Python 脚本用 `assert t.count(old) == 1` 匹配 `deny.toml` 中 `[licenses]` 段的空数组格式，实际文件里没有 `allow = []` 和 `exceptions = []`，报 `expect 1 got 0`。
- **根因**：上一轮有人改过 `deny.toml`（`cargo deny init` 生成的模板与手写版本不同），脚本按记忆中的格式编写，未先查看当前实际内容。
- **解决**：任何批量替换脚本编写前，先 `cat` 或 `grep -A N` 查看目标段落当前实际格式，再写 `old` 匹配串。脚本保留 `assert t.count(old) == 1` 保证唯一命中，失败即中断，绝不半改。
- **验证**：脚本输出 `OK: ...`，事后 `grep -A N` 确认改动正确。
- **教训**：文件被 fmt / init / 他人改过后格式不再一致。不确认当前格式就写脚本 = 猜测，违反协作规则。

## 11. `md_pool.rs::load_etf_txt` 是未完成代码（clippy `if_same_then_else`）

- **现象**：`let exchange = if 条件 { "SSE" } else { "SSE" };`，两分支返回相同值，clippy 报 `if_same_then_else`。
- **根因**：写码时打算按代码规则区分沪深交易所，`else` 分支尚未确定填什么，暂填 `"SSE"`。属未完成代码，不是风格问题。
- **业务规则（用户确认）**：

  - 沪市 ETF 期权代码第一位为 `1`，如 `10012448`
  - 深市 ETF 期权代码第一位为 `9`，如 `90008259`
  - 其他第一位 → 打印警告并跳过，清单人工核对后再加入

- **解决**：

  ```rust
  if code.len() != 8 || !code.as_bytes().iter().all(|b| b.is_ascii_digit()) {
      eprintln!("[ETF] 跳过非 8 位纯数字代码：{}", code);
      continue;
  }
  let exchange = match code.as_bytes()[0] {
      b'1' => "SSE",
      b'9' => "SZSE",
      other => {
          eprintln!(
              "[ETF] 未知交易所代码 {}，第一位='{}'，当前只认 1→SSE / 9→SZSE，请人工核对",
              code, other as char
          );
          continue;
      }
  };
  ```

- **验证**：ETF 清单中出现首位非 `1` / `9` 的代码时，日志给出警告，且该代码不进入分片。
- **教训**：clippy 的 `if_same_then_else` 往往不是「格式问题」而是死逻辑。看到该 lint 应先查业务意图，而不是简单合并分支或加 `#[allow]`。
