## 协作规则：不猜测，要原始信息

- **现象**：AI 助手对代码内容、文件状态、运行结果做猜测，猜的 100% 全错，浪费对话上下文。
- **规则**：不猜测任何代码内容、文件状态、运行输出。需要信息时直接要原始文件或让用户贴命令输出。
- **依据**：用户有桌面窗口，能直接复制原始文件发过来。

## 协作规则：优先要完整文件而非片段

- **现象**：反复 grep 看代码片段拼凑理解，效率极低。
- **规则**：需要看代码时直接要完整源文件（用户可桌面复制发送），不要反复看片段。
- **适用**：config.rs、main.rs、hard_limits.rs、md_pool.rs 等核心文件。

## 着眼项目整体，不留坑

- **规则**：任何改动以整个项目长期可维护为准，不以"当前单测通过 / 编译通过 / 当前小节点跑通"为完成标准。
- **禁止**：为让当前测试过而写临时旁路、硬编码、重复定义、跳过隔离验证。
- **要求**：每个改动先问"这会不会给后续节点（P1/P2/P3、重连、可观测性、多进程）留坑"。
- **判断依据**：配置是否单一来源、路径是否绝对可解析、进程间资源是否真隔离、错误是否显式暴露。
## 协作规则：未获授权不输出代码

- **规则**：只在用户明确说"改/写/开始"时才输出代码或修改方案。未获授权时，只陈述事实、只提问，不输出"预告的 diff""建议改法"。
- **理由**：未基于用户确认的完整上下文写出的修改方案，等同于猜测，浪费对话上下文。
- **边界**：读文件、跑命令、贴输出是事实，可主动做；写代码、给 diff、给改法是输出，必须等授权。

## 日常验证链（7 条，秒到分钟级，每次改完跑）

- `cargo fmt --all --check`（格式检查）
- `cargo clippy --all-targets -- -D warnings`（静态检查，警告即错误）
- `cargo nextest run`（跑测试，优先于 `cargo test`；文档测试 doctest 例外，用 `cargo test --doc`）
- `cargo audit`（漏洞扫描，读本地 advisory-db 安全公告库）
- `cargo deny --offline check`（依赖策略检查，四项全查：advisories 安全公告 / bans 禁用依赖 / licenses 许可证 / sources 来源）
- `cargo machete`（未使用依赖扫描，注意 feature-gated 特性门控误报，人工确认再删）
- `cargo doc --no-deps --workspace`（文档生成，不拉依赖文档，全工作区）
- 7 条总耗时控制在 3 分钟内。超时先 `cargo clean -p <crate>`（清单个 crate 编译产物）定位。

## 按需验证链（4 条，分钟到小时级，不日常跑）

- `cargo llvm-cov --workspace --html`（覆盖率报告，每周或发布前）
- `cargo semver-checks check-release`（发布库时检查语义化版本 semver 兼容）
- `cargo mutants`（变异测试，30 分钟到数小时，CI 按需）
- `cargo fuzz run <target>`（模糊测试，需先 `cargo fuzz init` 建 target 目标）
- **不能进日常链**：日常链塞慢命令，人就会跳过验证链直接跑代码，验证链等于没有。

## git commit -m 用单引号或 -F

- **规则**：`git commit -m` 的提交信息用**单引号**包裹，或多行用 `git commit -F message.txt`（从文件读提交信息）。不用双引号。
- **原因**：bash（命令行解释器）交互模式默认开启 history expansion（历史展开），双引号内 `!` 后跟非空格字符会被当历史引用，报 `event not found` 且整段丢失。
- **验证**：`git log -1 --format=%B <hash>`（查看完整提交信息）对比完整性。

##  改文件前先 cat / grep 确认当前格式

- **规则**：写批量替换脚本（sed 流编辑器 / python 脚本）前，先 `cat`（查看全文）或 `grep -A N`（查看目标段前后 N 行）确认目标段落**当前**实际格式，再写匹配串。不按记忆写脚本。
- **原因**：文件被 `cargo fmt`（格式化工具）/ `cargo deny init`（生成默认配置）/ 他人改过之后，格式不会和上次一致。按记忆写 = 猜测，违反"不猜测"规则。
- **配套**：脚本用 `assert t.count(old) == 1`（断言匹配唯一）保证唯一命中，失败立即中断不半改。
- **验证**：脚本输出 `OK:` + 事后 `grep -A N` 确认改动正确。

##  英文术语后跟中文

- **规则**：回复和文档里出现英文术语、缩写、标识符、文件名、路径名、变量名、函数名、库名时，后面必须跟中文解释。例：`flow_path`（会话流文件路径）、`md_pool`（行情连接池程序）、`.con`（CTP 会话流快照文件）、`ctp2rs`（CTP 的 Rust 绑定库）。
- **豁免**：`cargo` / `git` / `rust` / `clippy` / `fmt` / `deny` 等命令名和编程语言名视为专有名词，不强制跟中文。
- **理由**：项目里中英文混用多，纯英文术语积累起来看不懂。半年后回看不知道自己写的什么。
